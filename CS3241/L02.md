# 2D Graphics and OpenGL Primer

## OpenGL and GLUT

- **OpenGL** originates from the GL library (1992, Silicon Graphics). It handles graphics routines and window-event handling. It is an **API** (Application Programming Interface).
- **GLUT** — the OpenGL Utility Toolkit — sits on top of OpenGL and saves a lot of boilerplate (e.g., raw window-system programming with X-windows required pages of code just to open one empty window).

## First OpenGL Program

```c
#include <GL/glut.h>   // path depends on where glut.h is installed

void mydisplay(){
    glClear(GL_COLOR_BUFFER_BIT);   // clear the color buffer ("buffer" = memory space)
    glBegin(GL_POLYGON);
        glVertex2f(-0.5, -0.5);
        glVertex2f(0, 0.5);
        glVertex2f(0.5, -0.5);
    glEnd();
    glFlush();
}

int main()
{
    glutCreateWindow("CS3241: Hello OpenGL!");  // create a window with a title
    glutDisplayFunc(mydisplay);                 // register mydisplay as the display callback
    glutMainLoop();                             // start the window loop
}
```

Key points:

- `glutDisplayFunc(mydisplay)` passes a **function as a parameter** (registers a callback).
- **Default window "dimension"** is the coordinate range `(-1,-1)` to `(+1,+1)`, centered at the origin. This is the logical coordinate space, not the actual pixel size of the window.
- Default colors: background is **black**, drawing color is **white**.
- `glClear` clears a buffer (here the color buffer).

## OpenGL Function Naming Format

Format example: `glVertex3f(x, y, z)`

- `gl` — belongs to the GL library.
- `Vertex` — function name.
- `3` — number of dimensions (number of arguments).
- `f` — argument type is `float`.
- A trailing `v` (e.g., `glVertex3fv(p)`) means the argument `p` is a **pointer to an array**.

```c
GLfloat p[2] = {-0.5, 0.5};
glBegin(GL_POLYGON);
    glVertex2fv(p);
    ...
```

## `glBegin()` / `glEnd()` Pairs

`glBegin(<primitive>)` starts drawing a primitive; between `glBegin` and `glEnd` is a list of commands (vertices, normals, textures, etc.).

**OpenGL primitives** (argument to `glBegin`): `GL_POINTS`, `GL_LINES`, `GL_LINE_STRIP`, `GL_LINE_LOOP`, `GL_POLYGON`, `GL_TRIANGLES`, `GL_TRIANGLE_STRIP`, `GL_TRIANGLE_FAN`, `GL_QUAD_STRIP`.

## Polygon Issues

OpenGL only displays polygons **correctly** if they are:

- **Simple** — edges do not cross within the polygon.
- **Convex** — all interior angles are less than 180°.
- **Flat (coplanar)** — all vertices lie in the same plane (in 3D).

If these conditions are violated, OpenGL may or may not produce the desired output. Concave polygons drawn as a single vertex list render incorrectly. **Best practice: use triangles.**

## Color

- `glColor3f(r, g, b)` sets the current drawing color; components are in the range 0.0–1.0, ordered (red, green, blue).
- `glClearColor(r, g, b, a)` sets the clear/background color, but **nothing changes until `glClear` is called**.
- Color is assigned **per vertex**; assigning different colors to a polygon's vertices produces a smooth (interpolated) gradient across the primitive.

```c
glClearColor(1.0, 1.0, 1.0, 1.0);   // white background
glClear(GL_COLOR_BUFFER_BIT);
glBegin(GL_POLYGON);
    glColor3f(1.0, 0.0, 0.0); glVertex2f(-0.5, -0.5);  // red vertex
    glColor3f(0.0, 1.0, 0.0); glVertex2f(0, 0.5);      // green vertex
    glColor3f(0.0, 0.0, 1.0); glVertex2f(0.5, -0.5);   // blue vertex
glEnd();
glFlush();
```

# 2D Transformations

## Vector / Matrix Representations

- A 2D vector `(x, y)` can be written as a column or row matrix.
- **Homogeneous coordinates** add a third component: `[x, y, 1]`.
- If the last coordinate is `w` (not 1), the point represents `(x/w, y/w)`.
- If `w = 0`, the point is at infinity in the direction `(x, y)` (e.g., `(0,1,0)` is the point at the "north" most).
- Convention used here: the **column matrix** representation.

## Reference Frame

- Every coordinate is expressed relative to a **reference frame**. E.g., `p = (2,4)` means 2 units right of and 4 units above the origin of its reference frame.
- Applying a transformation is equivalent to **moving the reference frame**. If we apply `glTranslatef(4.0, 4.0, 0)` and then draw `p = (2,4)` in the NEW frame, it lands at `p' = (6.0, 8.0)` in the original frame.

## Translation

Move every vertex by a translation vector `t = (tx, ty)`. In homogeneous coordinates:

```
[x']   [1  0  tx] [x]   [x + tx]
[y'] = [0  1  ty] [y] = [y + ty]
[1 ]   [0  0  1 ] [1]   [  1   ]
```

Translation matrix:

```
T(tx, ty) = [1  0  tx]
            [0  1  ty]
            [0  0  1 ]
```

OpenGL function: `glTranslatef(x, y, z)`. Every primitive drawn **after** this call is translated. `glLoadIdentity()` resets the transformation back to the original reference frame.

## Rotation

Rotate all vertices around the origin, **anti-clockwise** by angle θ:

```
[x']   [cosθ  -sinθ  0] [x]   [x cosθ - y sinθ]
[y'] = [sinθ   cosθ  0] [y] = [x sinθ + y cosθ]
[1 ]   [ 0      0    1] [1]   [       1       ]
```

Rotation matrix:

```
R(θ) = [cosθ  -sinθ  0]
       [sinθ   cosθ  0]
       [ 0      0    1]
```

**Derivation:** represent a point in polar coordinates, `p = (r cosφ, r sinφ)` where `r = √(x²+y²)`. After rotating by θ, `p' = (r cos(θ+φ), r sin(θ+φ))`. Expanding with the angle-sum identities gives `p' = (x cosθ - y sinθ, x sinθ + y cosθ)`.

OpenGL function: `glRotatef(angle, x, y, z)` — a 3D rotation about the axis given by the vector `(x, y, z)`. For 2D, rotate about the z-axis: `glRotatef(60, 0, 0, 1)`.

## Scaling

Shrink or grow by factors `a` (x) and `b` (y); factors may be negative:

```
[ax]           [x]
[by] = S(a,b)  [y]
[1 ]           [1]
```

Scaling matrix:

```
S(a,b) = [a  0  0]
         [0  b  0]
         [0  0  1]
```

OpenGL function: `glScalef(x, y, z)`.

# Composite Transformations

- Multiple transformations can be chained, e.g. `p'' = T(0,1) R(10°) S(0.5,20) T(2,3) ... R(45°) p`.
- **Order matters.** The transformation nearest the point `p` (rightmost) is applied **first**.
- Whenever you add a new transformation, you add it to the **RIGHT** of the matrix product. Example: `p' = T(0,0.5) p`, then adding a rotation gives `p'' = T(0,0.5) R(-45°) p`.

Example in OpenGL (draws a bent line):

```c
void drawLine() {
    glBegin(GL_LINES);
        glVertex2f(0, 0);
        glVertex2f(0, 0.5);
    glEnd();
}

void mydisplay(){
    glLoadIdentity();      // reset transformation matrix to identity
    drawLine();
    glTranslatef(0, 0.5, 0);
    glRotatef(-45, 0, 0, 1);
    drawLine();
    glFlush();
}
```

# Matrix Stack

Resetting the transformation in the middle of drawing (via `glLoadIdentity()`) works but is **not good practice**. Instead, OpenGL provides a transformation (matrix) stack:

- `glPushMatrix()` — **save** the current transformation matrix onto the stack.
- `glPopMatrix()` — **restore** (retrieve) the previously saved matrix.
- The current transformation is a single **combined matrix** of all active transformations.
- Set the matrix mode with `glMatrixMode(GL_MODELVIEW)`.

Push/Pop lets you branch: apply some transforms, draw, then pop back to a saved state and branch differently. You can freely "mess up" the transformation within a Push/Pop pair without affecting the outer state.

### Example: drawing a "Y" / fork

```c
void drawFork()
{
    drawLine();
    glPushMatrix();
        glTranslatef(0, 0.5, 0);
        glPushMatrix();
            glRotatef(-45, 0, 0, 1);
            drawLine();
        glPopMatrix();          // resume to T(0,0.5)
        glPushMatrix();
            glRotatef(45, 0, 0, 1);
            drawLine();
        glPopMatrix();
    glPopMatrix();              // resume to nothing (identity)
}
```

A "nicer Y" adds `glScalef(0.5, 0.5, 0.5)` before each branch's `drawLine()` so the branches are shorter than the trunk.

### Fractal tree (recursion + matrix stack)

```c
void drawFork(int n)
{
    drawLine();
    if (n == 0) return;
    glPushMatrix();
        glTranslatef(0, 0.5, 0);
        glPushMatrix();
            glRotatef(-45, 0, 0, 1);
            glScalef(0.5, 0.5, 0.5);
            drawFork(n-1);
        glPopMatrix();
        glPushMatrix();
            glRotatef(45, 0, 0, 1);
            glScalef(0.5, 0.5, 0.5);
            drawFork(n-1);
        glPopMatrix();
    glPopMatrix();
}
```

Varying the translation, rotation angles, and scale factors (e.g., `glTranslatef(0,0.2,0)`, `glRotatef(-30,...)` / `glRotatef(60,...)`, `glScalef(0.7,...)` / `glScalef(0.4,...)`) produces more natural, asymmetric trees.

# Fractals

- A fractal curve is built from an **initiator** (a starting shape) and a **generator** (a rule that replaces each segment). Applying the generator repeatedly, toward infinity, yields the fractal.
- Example: the **Koch snowflake** — initiator is a triangle; each edge is repeatedly replaced by the generator, producing an increasingly detailed snowflake boundary.
- The **Sierpinski triangle** is another classic fractal (self-similar subdivided triangles).
- Fractal recursion combined with the OpenGL matrix stack is the basis for procedurally generated trees (later extended to 3D).
